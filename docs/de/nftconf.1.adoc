== Name

nftconf - deklarative nftables-Konfiguration mit Live-Abgleich

== Aufruf

*nftconf* [_GLOBAL_]... _CMD_ [_OPTION_]... [_DATEI_]...

== Beschreibung

*nftconf* liest eine kleine deklarative Konfigurationssprache und gleicht sie
mit dem laufenden *nftables*(8)-Regelwerk ab. Jede logische Regel trägt einen
Besitzerkommentar, damit *load*, *unload* und *daemon* nur eigene Regeln ändern.

NAT wirkt auf prerouting/output/postrouting und öffnet *INPUT* *nicht*.
Ports für die lokale Zustellung brauchen explizites *whitelist*/*accept*
(optional *shield on*).

== Befehle

*load* _DATEI_::
  Gleicht _DATEI_ mit dem Live-Regelwerk ab. Eine Anweisung wird eine
  nft-Regel. *-c, --compact* fasst passende allow/deny in nft-Sets zusammen.

*unload* _DATEI_::
  Entfernt eine Live-Regel nur bei vollständiger Übereinstimmung.
  *-f, --force* zerlegt eine übrig gebliebene kompakte Regel und entfernt
  so viele Atome wie möglich.

*status* _DATEI_::
  Zeigt Abweichungen zwischen Soll und Ist.

*check* _DATEI_::
  Parst und gibt aufgelöste nft-Regeln aus.

*show* _DATEI_::
  Status je Anweisung, Spalte Breite 8: *on* (vollständig live),
  *N/M* (teilweise), *---* (nicht geladen), *xxx* (Syntaxfehler).

*daemon* _DATEI_::
  Überwacht _DATEI_ (und Includes) und lädt bei Änderungen neu.
  Pidfile standardmäßig */run/nftconf.pid*; zweite Instanz wird abgelehnt.

*stop*::
  Stoppt den Daemon über das Pidfile (*--pid*).

*convert* _DATEI_...::
  Schreibt konsolidierte *nftables.d/\*.nft*.

*help*::
  Zeigt die Hilfe.

== Globale Optionen

*-v, --verbose*::
  Debug-Protokoll (wiederholbar).

*-q, --quiet*::
  Nur Fehler.

*-h, --help*::
  Hilfe anzeigen.

*--version*::
  Version ausgeben und beenden.

== Konfliktpolitik

Gilt für *load*, *daemon* und *convert*:

(Standard)::
  Abbruch bei Konflikt mit bestehenden nft-Einstellungen.

*-f, --force*::
  Konfliktierende Live-Regeln überschreiben (*load*).

*-n, --no-clobber*::
  Konfliktierende Änderungen überspringen.

*--dry-run*::
  Aktionen nur anzeigen.

*load -c/--compact*::
  Passende Anweisungen in nft-Sets zusammenfassen.

*unload -f/--force*::
  Übrig gebliebene kompakte Regeln zerlegen und passende Atome entfernen.

== Konfigurationssprache

Eine Datei enthält eine Anweisung pro Zeile. Leerzeilen werden ignoriert.
*#* beginnt einen Kommentar (außer in Anführungszeichen). Ein Kommentar
in derselben Zeile wie eine NAT- oder Filteranweisung wird in den
nft-Regelkommentar nach dem Besitzertag kopiert. Der erste Token
ist die Anweisung; Namen und Schlüsselwörter sind unabhängig von der
Groß-/Kleinschreibung. Ein Kontext gilt bis zur nächsten Kontextanweisung.

=== Kontext

*table*, *interface*, *address*, *dest address* / *dest interface*,
*priority*, *shield on|off*, *include*.

=== Ports (tcp / udp / sctp / dccp)

Nach einem Port-Protokoll: einzelner Port, inklusiver Bereich, oder Liste
(Leerzeichen und/oder Kommas). Ein Element wird als Skalar/Bereich
ausgegeben; zwei oder mehr als anonymes nftables-Set.

----
allow incoming tcp 22
allow incoming tcp 8000-8080
allow incoming tcp 80 443 1080 8000-8080
deny incoming tcp 33
allow outgoing ip 10.0.0.0/8 tcp 443
nat tcp 80 443 8000-8080 to 10.0.0.50
----

Ports 0–65535; *HIGH* ≥ *LOW*. Optional *ADDR:PORT* (oder *[IPv6]:PORT*)
als Präfix. Sonst liefern *address* / *interface* *ip daddr*. Listen gelten
für Filter- und NAT-Anweisungen (vor *to*), nicht für *icmp* / *ct*.

=== NAT und Filter

*nat* / *dnat* / *snat* _PROTO_ _PORT_... *to* _DEST*, *masquerade*,
*redirect*. NAT öffnet *INPUT* nicht.

*whitelist* / *allow* sind Aliase von *accept*. Mit *shield on* landen sie
in der Shield-Kette. Alles nach *reject … with* geht an nftables
(*tcp reset*, …).

Siehe *guide.md* und `info nftconf`.
